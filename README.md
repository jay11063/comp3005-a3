## Requirements

- PostgreSQL 16 (any recent version works)
- Python 3.10 or later
- Python packages: `psycopg2-binary`, `python-dotenv`

## Setup

### 1. Create the database

In pgAdmin, right-click **Databases**, choose **Create > Database**, and name it
`student_db`. From a terminal the equivalent is:

```
createdb -U postgres student_db
```

### 2. Create the table and load the initial data

`sql/schema.sql` creates the `students` table and inserts the three initial
records. Run it against the database you just created:

```
psql -U postgres -d student_db -f sql/schema.sql
```

In pgAdmin, open the Query Tool on `student_db`, load `sql/schema.sql` with the
folder icon, and run it.

### 3. Install the dependencies

```
pip install psycopg2-binary python-dotenv
```

### 4. Configure the connection

Create a file named `.env` in the project root. It is listed in `.gitignore`, so
it is not part of this repository and has to be created locally:

```
DB_HOST=localhost
DB_PORT=5432
DB_NAME=student_db
DB_USER=postgres
DB_PASSWORD=your_password_here
```

Every variable except `DB_PASSWORD` has a default in `src/app.py`, so a file that
only sets the password works as long as the other values match the list above.

## Running the application

```
python src/app.py
```

The application prints a menu and keeps running until option 0 is chosen:

```
1. List all students
2. Add a student
3. Update a student's email
4. Delete a student
0. Exit
```

Options 2, 3 and 4 prompt for the values they need. Dates are entered as
`YYYY-MM-DD`.

## Functions

| Assignment function | Implementation | Description |
| --- | --- | --- |
| `getAllStudents()` | `get_all_students()` | Selects every row of `students` ordered by `student_id` and prints them as a table. Prints a message when the table is empty. |
| `addStudent(first_name, last_name, email, enrollment_date)` | `add_student(first_name, last_name, email, enrollment_date)` | Inserts a new row. The caller supplies all four values; `student_id` is generated by the database. |
| `updateStudentEmail(student_id, new_email)` | `update_student_email(student_id, new_email)` | Checks that the student exists, then updates that row's `email`. |
| `deleteStudent(student_id)` | `delete_student(student_id)` | Checks that the student exists, then deletes that row. |

Each function opens its own connection, uses parameterised queries so that values
are never concatenated into SQL, commits the transaction, and reports database
errors instead of raising them to the user.
